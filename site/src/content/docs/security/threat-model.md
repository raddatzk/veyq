One table, one row per adversary, each against what is **built today**. It merges the security model's
[threat table](https://github.com/raddatzk/veyq/blob/main/docs/crosscutting/security-model.md#threat-model--trust-boundaries)
with its per-attack
[What holds today](https://github.com/raddatzk/veyq/blob/main/docs/crosscutting/security-model.md#what-holds-today-on-a-client-the-operator-does-not-serve)
table, which is the ceiling for every claim here. Each row points at the ADR that decides it.

:::caution[Which client the active-operator rows describe]
The *active operator* rows hold on **a client the operator does not serve**. On **operator-served web** — someone
else's instance and the web client it ships — the answer to every one of them is **"passive operator only"**: an
active operator can serve tampered code that captures keys and plaintext
([ADR 0026](https://github.com/raddatzk/veyq/blob/main/docs/decisions/0026-client-trust-tiers.md)). Self-hosted, the
operator is you and the rows are moot. See [Start here](/veyq/security/start-here/) for the tiers.
:::

## The table

"Can" lists what the adversary achieves today; "Cannot" what the build stops. Server-side checks are layer-1
access control and hold only under an honest operator; anything listed as stopping the *operator* is a check a
client makes with a key the operator lacks.

## What stays open

Once every active-operator attack above reads *Cannot*, these remain, each decided where the table points
(security model § What holds today, "What stays open"):

- A key substituted before anyone pinned it, between members who never compare safety numbers. This also covers a
  device with no trust-state mark yet, a genuine tenant invite redeemed with the operator's key, and a shared grant
  signed by a granter identity the operator fabricated. Key Transparency would close it and is not built; nor is
  the opt-in strict mode that would refuse unverified members, whose shape is still open
  ([Roadmap](/veyq/security/roadmap/)).
- A rotation withheld from members who never saw it (a fork), and rotations queued to another key-holder, which
  know only the server's member list. Detecting a fork needs a transparency mechanism (ADR 0024 § Guarantee).
- A departing member who tagged a sockpuppet with the operator's help before the removal; closing it needs a
  member roster the client holds itself (ADR 0020, ADR 0024).
- An attacker who both reads a pairing QR and runs the relay (ADR 0059 §11).
- Item favorites, sealed under the first epoch by choice, with the freshness and count limits in the table
  (ADR 0068).
- A removed member holding old share links, until they are re-issued, as in the table (ADR 0075).
- The names a Memory's guests gave, to an operator holding a view or contribute link of that Memory; accepted,
  because that link already decrypts every medium of the Memory
  ([ADR 0030](https://github.com/raddatzk/veyq/blob/main/docs/decisions/0030-contributor-public-share.md) point 8).

## Two notes on revocation and sharing

**Revocation has two layers.** Layer 1 stops serving a revoked member or link at once, with no keys involved.
Layer 2 rotates the scope's content key forward into a new epoch granted to the remaining members, which protects
against a revoked party who cached ciphertext *and* a malicious operator feeding them new ciphertext. Whether
layer 2 fires is a per-scope policy: groups rotate on every removal, the tenant only on an explicit re-key,
personal scopes never
([security model § Revocation](https://github.com/raddatzk/veyq/blob/main/docs/crosscutting/security-model.md#revocation--two-layers),
[ADR 0025](https://github.com/raddatzk/veyq/blob/main/docs/decisions/0025-forward-secrecy-policy-per-scope.md)).
A rotation does not revoke a share: a shared Memory key is wrapped independently of the scope key, so links are
revoked or re-issued separately.

**A share password is an access-control gate, not a cryptographic one.** The content stays encrypted under the
link's key; the password decides what the server serves. It defends a leaked link against an honest operator,
not against a malicious one who bypasses the check for someone holding the URL fragment
([ADR 0037](https://github.com/raddatzk/veyq/blob/main/docs/decisions/0037-password-protected-shares.md)). The
viewer a link opens is operator-served web, so it is passive-operator-safe only.
